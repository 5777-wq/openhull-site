01 — 简介 / INTRODUCTION

一份任务书，一整套初步设计

船舶初步设计的知识内核——教科书里的经验公式、系列试验图谱、规范里的查表计算—— 本来就是公开的。真正缺的，是一层把它们编排成完整设计循环的自动化。 OpenHull 把这些知识数字化为可组合、可验证的 Python 模块， 再由 AI 智能体按《项目宪法》编排成流水线。

人负责专业判断，AI 负责代码与搬运数据的手。

02 — 开发进程 / DEVELOPMENT

六个阶段，验收只认数字

每个任务颗粒度不超过一晚。AI 先出实现方案，人审定公式，编码完成后再对公开基准船数据 逐项核对误差——"完成了"三个字不算数，数字达标才算数。

  1. 阶段 0 · 立项与立宪

    2026-09 已完成

    项目宪法《AGENTS.md》九节：单位制、公式白名单、适用边界守卫、禁区与验收容差表；例题船选定 JBC + Series 60；设计任务书 TB-001 获批；代码骨架落地，21 项测试全绿。

  2. 阶段 1 · 主尺度与静水力内核

    v0.1 进行中

    从载重吨与航速反推主尺度（算法可插拔注册表：载重系数法 / Watson 1977 / 母型船比例法），重量浮力平衡迭代，辛普森积分静水力内核，初稳性与干舷校核——全部对 JBC 实船值控制误差。当前进行到任务 1.2 · 主尺度初估。

  3. 阶段 2 · 参数化型线生成

    v0.2 规划中

    母型船型值数字化，Lackenby 变换把 Cb 精确变换到目标值，生成横剖面 / 半宽水线 / 纵剖线三视图，光顺性数值检查，静水力改吃真型值，DXF 图纸输出。

  4. 阶段 3 · 性能闭环

    v0.3 规划中

    Holtrop-Mennen 阻力预报、推进与航速反算、螺旋桨初步设计、大倾角稳性与 IMO 衡准逐条校核；最后由智能体编排自动寻优——在约束内扫描主尺度空间，输出可行方案集与帕累托权衡图。

  5. 阶段 4 · 出图与报告

    v0.4 规划中

    静水力曲线图、总布置简图、自动生成带编号图表与结论段的设计报告——一条命令从任务书跑到成果包，成品可直接当课程设计提交。

  6. 阶段 5 · 开源发布

    v1.0 规划中

    v1.0 的定义：两种以上不同船型跑通全流程且验证达标，附完整文档、学术引用条目与 CI。 十语 README 已提前就位。

03 — 优势 / ADVANTAGES

把工程纪律写进宪法

A-01

可追溯

每一个输出结果都必须可追溯至某条公式或公开文献。经验公式强制声明适用范围——Fn、Cb 超出边界的输入一律报错拒绝，而不是悄悄给出一个行家一眼看穿的错误数字。

A-02

基准验证优先

与 JBC、Series 60 等公开基准船数据逐项对比，验证优先于新功能开发。静水力误差 <1%、KM 误差 <2%、TPC 误差 <3%——每个数字分开报告，藏在哪个总评里都不行。

A-03

人机各司其职

公式对不对、量级合不合理，由工程师拍板；代码、集成、数据搬运交给 AI。公式先入白名单再实现，页码级出处备查——AI 幻觉公式在制度上就无法进入代码库。

A-04

解释性报错

数据结构逐字段与跨字段校验，报错必须讲清四件事：哪个字段、输入了什么、允许范围是什么、物理或数学上为什么——比如 Cb=1.5 会被告知"排水体积塞不进外接矩形，所以 Cb ≤ 1"。

A-05

算法可插拔

每种算法自带 id、出处与适用范围元数据，挂在注册表上随取随用；任务书可以按 id 钉死算法，未来的前端下拉框直接生成——工程知识以可组合的方式沉淀。

A-06

彻底开源

MIT 许可，不替代解算器、不遥控 CAD 软件，只做"替代人在软件间搬运数据的手"。核心资产是仓库里经得起核对的 Python 代码与文档，谁都可以审阅、复算、 fork。

POSITION · 卡位

商业船舶软件垄断的是交付环节，而初步设计的知识内核是公开的。 2026 年的生态调研显示：基础件齐全、学术先例俱在， 唯独"AI 智能体编排层"无人做成—— 全世界尚无同类开源项目，这就是 OpenHull 的核心价值。
